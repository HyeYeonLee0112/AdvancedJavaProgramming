## 1. 시작 상태와 이번 결과물

#34에서 카드 ID로 모델과 화면을 연결할 수 있어야 한다. 이동·순서는 현재 메모리에만 남긴다.

이 문서의 파일은 app/src/main/java 아래 패키지 경로 기준의 제안이다. 이미 파일이 있다면 먼저 읽고 재사용한다. 이 안내서가 실제 파일이나 기능을 만들어 놓은 것은 아니다.

이번 결과물은 직접 작성한 코드, 실행 순서, 아래 테스트의 실제 결과, 선택한 정책과 짧은 회고다. 선행 단계가 실패하면 먼저 그 문제를 해결한다.

## 2. 먼저 이해할 개념

마우스 위치와 카드 위치가 서로 다른 기준이면 클릭 순간 카드가 튄다. 보드 좌표는 보드 왼쪽 위를 기준으로 한 위치다. 누름에서 잡은 지점의 차이를 기억하고 이동 중 그 차이를 빼야 한다.

겹침 순서는 어느 카드를 앞에 그리는지다. toFront는 화면에만 적용되므로 저장할 데이터의 순서 값도 갱신해야 한다.

## 5. 사람의 의도 → 실행 흐름

카드 한가운데를 잡았으면 마우스를 따라 카드 한가운데가 움직여야 한다. 저장 후 다시 그려도 같은 위치와 순서여야 한다.

```text
누름: 마우스 위치를 보드 좌표로 변환 → 카드 원점과 차이 기억
드래그: 보드 좌표 - 차이 → 경계 정책 → 화면 임시 이동
놓음: 최종 위치를 모델에 기록 → 다음 표시 순서 부여 → 앞에 표시
생성·수정: 승인된 카드의 표시 순서도 갱신
재그리기: 표시 순서로 정렬해 차례대로 붙임
```

위 순서를 자신의 말로 먼저 설명한다. 다음 예제로 API 하나를 확인한 뒤 서비스 흐름은 직접 작성한다.

## 6. 아주 작은 예제와 읽는 법

#34의 start에서 board와 note를 만든 뒤 붙이는 좌표 관찰 예제다. import javafx.geometry.Point2D를 추가한다. 아직 드래그 구현은 아니다.

```java
note.setOnMousePressed(event -> {
    Point2D point = board.sceneToLocal(
        event.getSceneX(), event.getSceneY());
    double offsetX = point.getX() - note.getLayoutX();
    double offsetY = point.getY() - note.getLayoutY();
    System.out.println(offsetX + ", " + offsetY);
});
```

sceneToLocal은 전체 화면 위치를 보드 안 위치로 바꾼다. offset은 카드 왼쪽 위에서 잡은 위치까지의 거리다. 다음 이벤트에서도 쓰려면 카드별 드래그 상태에 보관해야 한다. 한 전역 변수를 모든 카드가 공유하도록 만들지 않는다.

이 예제의 생략한 책임을 확인한다. 예제가 실행된 것과 이슈의 기능이 완성된 것은 다르다. 동작하는 예제에 한 기능씩 더하고 확인한다.

## 7. 직접 구현하는 순서

1. 카드 왼쪽 위와 가운데를 눌러 출력 차이가 다른지 관찰한다.
2. 카드별로 눌렀을 때 차이를 기억한다. 놓으면 드래그 상태를 끝낸다.
3. 드래그 이벤트에서 보드 좌표와 차이로 새 원점을 계산한다.
4. 놓는 이벤트에서만 최종 좌표를 모델에 기록한다. 이동 중 출력 로그는 과도하게 남기지 않는다.
5. 두 카드를 겹치고 생성·수정·이동 뒤 앞으로 보내는 처리를 연결한다.
6. 화면의 toFront 호출뿐 아니라 모델 순서 값을 바꾼다. 모든 카드를 모델 순으로 다시 그려 동일 결과를 확인한다.
7. 좌표 계산은 계산 부분과 이벤트 부분으로 나눠, 창 없이 경계 계산을 시험할 수 있게 한다.

각 단계가 끝날 때 기대한 동작이 실제로 되는지 확인한다. 실패하면 첫 오류와 재현 입력을 남기고 다음 단계로 넘어가지 않는다.

## 8. 예외·경계값 테스트

| 재현 방법 | 기대 결과 | 어긋날 때 확인 |
|---|---|---|
| 가운데·오른쪽 아래 잡고 이동 | 잡은 지점 유지 | 좌표 기준과 offset |
| 보드 영역이 화면에서 이동한 뒤 드래그 | 카드가 튀지 않음 | scene 위치 직접 사용 여부 |
| 끝까지 이동 | 정한 경계 정책과 일치 | 카드 폭·높이 고려 |
| A·B 겹친 뒤 A 이동·수정 | A가 최상단 | 데이터 순서 갱신 |
| 모델로 전체 화면 재생성 | 이전 순서·위치 유지 | 화면만 변경했는지 |
| 같은 카드를 연속 이동 | 이전 드래그 상태가 남지 않음 | 누름·놓음 초기화 |

### 실제 결과 기록

```text
코드 버전 / 실행 환경:
검사 항목:
준비한 계정·보드·데이터:
내가 한 행동:
기대 결과:
실제 결과: 미실행 / 통과 / 실패
증거와 오류:
원인·수정:
같은 조건 재검증:
```

검사표는 기대 결과다. 실제로 실행하기 전에는 체크하지 않는다. 개인 암호·세션·민감한 경로는 증거에서 제외한다.

## 9. 리팩터링·회고·완료 기준

동작을 확인한 뒤 긴 이벤트에서 계산·검사·저장 책임을 분리한다. 처음부터 제안된 모든 클래스를 빈 파일로 만드는 데 시간을 쓰지 않는다.

- [ ] 잡은 지점이 유지된다.
- [ ] x·y·순서가 모델에 기록된다.
- [ ] 생성·수정·이동 후 순서가 재그리기에도 유지된다.
- [ ] 보드 크기·경계 정책과 테스트를 남긴다.

리뷰 질문: scene 좌표와 board 좌표를 그림으로 설명한다. toFront만 사용하면 재시작 때 왜 순서가 사라지는가? 세 마우스 이벤트와 모델 갱신 코드를 리뷰받는다.

완료 보고에는 바꾼 파일, 확인한 테스트, 아직 남은 실패/미정, 다음 단계에 넘길 데이터와 규칙을 적는다. 핵심 구현과 제출 설명은 직접 작성하고 AI에는 개념·힌트·작은 예제·내 코드 리뷰를 요청한다.
