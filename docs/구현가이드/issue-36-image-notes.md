# #36 · 이미지 포스트잇·미리보기

선택한 이미지가 비율을 유지해 카드로 나타난다. 취소·잘못된 파일은 카드를 만들지 않으며, 처리 중 화면이 반응한다.

상태: 학습·구현 안내서. 아래 동작은 완료 목표이며 현재 구현됐다는 뜻이 아니다.

## 1. 시작 상태와 이번 결과물

#34의 카드 생성 흐름에 이미지 입력을 추가한다. 다른 PC와 공유하는 이미지 저장은 #38·#41에서 연결한다.

이 문서의 파일은 app/src/main/java 아래 패키지 경로 기준의 제안이다. 이미 파일이 있다면 먼저 읽고 재사용한다. 이 안내서가 실제 파일이나 기능을 만들어 놓은 것은 아니다.

이번 결과물은 직접 작성한 코드, 실행 순서, 아래 테스트의 실제 결과, 선택한 정책과 짧은 회고다. 선행 단계가 실패하면 먼저 그 문제를 해결한다.

## 2. 먼저 이해할 개념

파일 선택은 경로를 얻는 일이고 이미지 읽기는 그 파일을 해석하는 일이다. 확장자가 png라고 실제 PNG인 것은 아니다. 파일 선택 성공을 카드 저장 성공으로 표시하면 안 된다.

Image는 이미지 데이터, ImageView는 이를 화면에 그리는 부품이다. 모델에 ImageView를 넣으면 저장·통신이 화면에 묶인다.

## 3. 지금 정할 것과 미룰 것

- 지금: FileChooser와 로컬 미리보기. 선택·검사·읽기 결과를 구분한다.
- 짧게 이해: Task는 화면을 막지 않고 작업한 결과를 받아오는 JavaFX 도구다.
- 나중: 서버 업로드·이미지 ID·DB 저장과 부분 실패 처리는 #38·#41.
- 제외: 그림판·원본 편집·이미지 생성 AI.

허용 형식, 파일 바이트 상한, 픽셀 크기 상한을 이슈에 기록한다. 파일 용량이 작아도 압축된 이미지의 픽셀 수가 매우 클 수 있다.

## 4. 파일별 책임과 연결

| 제안 파일 | 맡길 일 |
|---|---|
| client/image/ImageLoader.java | 파일 검사·읽기·미리보기 크기 계산 |
| client/ui/StickyNoteView.java | ImageView와 로딩·실패 표시 |
| model/StickyNote.java | 글/이미지 종류와 이미지 식별자 |
| client/BoardController.java | 읽기 성공 후 카드 생성, 취소 처리 |

ImageLoader가 성공 결과를 돌려주고 Controller가 카드 생성 여부를 정한다. UI의 파일 경로는 다른 PC에서 유효한 공유 주소가 아니다.

## 5. 사람의 의도 → 실행 흐름

이미지를 고른 사용자는 미리보고 추가한다. 파일을 읽지 못하면 이유를 알고 다시 선택할 수 있어야 한다.

```text
이미지 추가 클릭 → 파일 선택
취소면 종료 → 크기·형식 검사
화면에 처리 상태 표시 → 작업 스레드에서 읽기
실패면 이유 표시 / 성공이면 미리보기와 카드 생성
서버 연결 이후: 업로드·저장 승인 뒤 확정 표시
```

위 순서를 자신의 말로 먼저 설명한다. 다음 예제로 API 하나를 확인한 뒤 서비스 흐름은 직접 작성한다.

## 6. 아주 작은 예제와 읽는 법

먼저 버튼 이벤트 안에서 선택·취소만 확인한다. #33의 start에서 만든 stage를 사용한다. import java.io.File, javafx.stage.FileChooser를 추가한다.

```java
FileChooser chooser = new FileChooser();
chooser.setTitle("이미지 선택");
File selected = chooser.showOpenDialog(stage);
if (selected != null) {
    System.out.println(selected.getName());
}
```

showOpenDialog가 null이면 사용자가 취소했다. 선택 필터는 편의 기능이고 보안 검사가 아니다. 이 예제는 파일을 읽거나 카드에 붙이지 않는다. 출력에 전체 개인 경로를 남길 필요는 없다.

이 예제의 생략한 책임을 확인한다. 예제가 실행된 것과 이슈의 기능이 완성된 것은 다르다. 동작하는 예제에 한 기능씩 더하고 확인한다.

## 7. 직접 구현하는 순서

1. 선택·취소를 실행해 결과가 다른지 확인한다.
2. Files.size 등으로 파일 크기를 검사하고 허용 규칙을 분리한다.
3. 작은 정상 이미지 한 장을 Image로 읽고 ImageView로 표시한다. 비율 유지와 표시 크기를 확인한다.
4. 읽기 실패를 검사해 성공한 경우에만 모델에 카드를 추가한다.
5. 느린 읽기 작업을 Task로 옮긴다. call 안에서는 화면을 건드리지 않고, 성공·실패 콜백에서 갱신한다.
6. 연속 선택에서 먼저 시작한 느린 결과가 최신 선택을 덮지 않도록 요청 식별이나 취소 규칙을 정한다.
7. 이미지 교체·카드 삭제 시 임시 파일/메모리 참조 정리 위치를 기록한다. 서버 이미지 ID로 바꿀 연결 지점을 표시한다.

각 단계가 끝날 때 기대한 동작이 실제로 되는지 확인한다. 실패하면 첫 오류와 재현 입력을 남기고 다음 단계로 넘어가지 않는다.

## 8. 예외·경계값 테스트

| 재현 방법 | 기대 결과 | 어긋날 때 확인 |
|---|---|---|
| 파일창 취소 | 카드 개수 그대로 | null 처리 |
| 정상 가로·세로 이미지 | 비율 유지 | fit 크기와 preserveRatio |
| 이름만 png인 파일·깨진 파일 | 오류 안내, 카드 없음 | 디코딩 실패 검사 |
| 상한 직전·초과 파일 | 기록한 한도 적용 | 바이트와 픽셀 별도 검사 |
| 느린 이미지 읽기 중 버튼 클릭 | 화면 반응 | 화면 스레드의 I/O |
| 읽기 중 창 종료·다른 파일 선택 | 오래된 결과가 잘못 반영되지 않음 | 작업 취소·요청 ID |

### 실제 결과 기록

```text
코드 버전 / 실행 환경:
검사 항목:
준비한 계정·보드·데이터:
내가 한 행동:
기대 결과:
실제 결과: 미실행 / 통과 / 실패
증거와 오류:
원인·수정:
같은 조건 재검증:
```

검사표는 기대 결과다. 실제로 실행하기 전에는 체크하지 않는다. 개인 암호·세션·민감한 경로는 증거에서 제외한다.

## 9. 리팩터링·회고·완료 기준

동작을 확인한 뒤 긴 이벤트에서 계산·검사·저장 책임을 분리한다. 처음부터 제안된 모든 클래스를 빈 파일로 만드는 데 시간을 쓰지 않는다.

- [ ] 취소·실패와 성공 상태를 구분한다.
- [ ] 이미지 표시·교체가 가능하고 비율이 유지된다.
- [ ] 형식·바이트·픽셀 제한을 문서화한다.
- [ ] 느린 처리 중 화면 응답과 오래된 결과 처리 증거를 남긴다.

리뷰 질문: 사용자 PC의 경로를 서버에 문자열로 보내면 다른 사람은 왜 못 보는가? 읽기 결과와 저장 승인 결과를 구분할 방법은? 선택·검사·작업 콜백 코드를 리뷰받는다.

완료 보고에는 바꾼 파일, 확인한 테스트, 아직 남은 실패/미정, 다음 단계에 넘길 데이터와 규칙을 적는다. 핵심 구현과 제출 설명은 직접 작성하고 AI에는 개념·힌트·작은 예제·내 코드 리뷰를 요청한다.
