# 기말 프로젝트 기획서 — 포스트잇 협업 보드 (가칭)

상태: 사용자 결정과 학습 목표를 정리한 작업 초안. 제출용 최종본 아님.
기획 변경: 글·그림 릴레이에서 포스트잇 협업 보드로 전환한다.

## 1. 기획 의도

여러 사람이 하나의 보드에 글과 이미지를 카드로 붙이고, 카드를 옮기며 생각을 함께 정리하는 서비스다. 수업 내용 정리, 브레인스토밍, 팀 회의에 사용할 수 있다. 구체적인 대표 사용 상황과 제품명은 사용자가 결정한다.

- JavaFX 데스크톱 앱과 Java 서버로 구현한다.
- 혼자 보드를 만들고 사용하거나, 공유 코드로 다른 사용자가 참여한다.
- 모든 사용자는 권한이 있는 보드의 카드를 볼 수 있다.
- 기존 릴레이의 4~6인 제한, 작성 순서, 20초 글쓰기, 60초 그림, 무작위 배정 규칙은 폐기한다.
- 5분은 발표 시연 목표로 유지하며 서비스 이용 시간에는 제한을 두지 않는다.

## 2. 핵심 사용자 흐름

1. 회원가입·로그인 후 내 보드를 확인한다.
2. 새 보드를 만들거나 공유 코드로 다른 보드에 참여한다.
3. 텍스트·이미지 카드를 작성하고 내용을 수정한다.
4. 카드를 드래그하여 배치하고 다른 사용자의 변경을 실시간으로 확인한다.
5. 앱을 다시 실행해 저장된 보드를 이어서 사용한다.
6. 보드 삭제 전 저장된 스냅샷을 보관함에서 다시 열고, 소유자가 공개 여부를 관리한다.

## 3. 필수 기능

참고 서비스 `jungle-mini-project-board`의 구현 기능을 전부 유지한다. 상세 요구사항은 [PRD](기말프로젝트_PRD.md)의 B-01~B-13을 기준으로 한다.

- 회원가입·로그인·로그아웃.
- 보드 생성·조회·제목 변경·공유 식별자 변경·내 보드 목록.
- 텍스트·이미지 카드 생성·조회·수정·삭제, 드래그, 겹침 순서.
- 작성자와 보드 소유자의 편집 권한.
- 텍스트 500자, 보드당 카드 300개 제한.
- 같은 카드의 동시 수정 충돌 처리.
- 같은 보드를 보고 있는 사용자 사이의 실시간 변경 전파.
- 보드 삭제 전 이미지 스냅샷, 내 스냅샷 보관함, 공개 전환·갤러리, 스냅샷 삭제.
- JDBC 저장과 클라이언트 썸네일 메모리 캐시.

보드 소유자는 보드와 전체 카드를 관리하고, 일반 참가자는 자기 카드를 관리한다. 스냅샷의 공개·삭제는 소유자 권한으로 처리한다. 게임 참가자 공동 소유와 게임 원본·편집본 분리 정책은 더 이상 적용하지 않는다.

## 4. 과목 응용과 기존 기술 선택

| 수업·학습 기술 | 자연스럽게 활용하는 기능 |
|---|---|
| 이벤트 처리 | 카드 작성 버튼, 텍스트 입력, 드래그, 삭제 요청 |
| 그래픽·화면 구성 | 포스트잇 표시, 위치·겹침 순서, 이미지 미리보기, 보드 스냅샷 |
| 멀티스레드 | 네트워크 수신·DB 작업·이미지 처리를 화면 처리와 분리하여 앱 응답 유지 |
| 소켓 | 같은 보드의 카드 생성·수정·이동·삭제를 여러 클라이언트에 전달 |
| JDBC | 사용자·보드·참여 관계·카드·스냅샷을 저장하고 재실행 후 복원 |
| MVC·CRUD | 화면, 편집 규칙, 통신, 저장의 책임을 나누고 데이터 생성·조회·수정·삭제 구현 |
| 간단한 캐시 | 보관함에서 이미 받은 스냅샷 썸네일 재사용 |
| RMI | 최신 주차표의 필수 항목으로 확인되지 않음. 실제 수업 요구 확인 후 판단 |

개발 환경은 기존 결정인 Eclipse + Temurin JDK 21 + Maven + JavaFX를 유지한다. Swing 수업 실습은 별도로 진행한다. JavaFX 사용 허용 여부, JavaFX 버전, DB 제품과 JDBC 드라이버는 확인·결정이 필요하다.

## 5. 범위와 추가 기능 후보

처음에는 위 필수 기능의 연결과 검증에 집중한다. 직접 그리는 그림판은 현재 필수 범위에서 제외하며 이미지 첨부는 유지한다. 포스트잇 색상 선택은 추가 기능 후보로 둔다.

실시간 공동 그림판, AI 생성, 채팅, 무한 캔버스는 필수로 추가하지 않는다. 지원 인원 상한과 이미지 파일 규격은 구현 환경을 확인한 뒤 결정한다.

## 6. 확인·보완할 사항

- 대표 사용 상황, 제품명, 화면 스케치.
- 공유 코드로 참가자를 등록하는 방식과 코드 변경 후 기존 참가자의 권한 정책.
- 보드 공개와 스냅샷 공개의 관계.
- 이미지 용량·형식·보드 크기와 지원 인원 상한.
- 교수자의 JavaFX 사용 허용 및 1인 개발 허용 여부.
- 본인이 선택한 이유와 직접 진행한 사용성 테스트 결과.
- 시연 구성: 입장 → 카드 작성·이동 → 두 화면 동기화 → 저장·재조회 → 스냅샷 확인. 5분 내 시연 가능 여부를 실제로 측정한다.

GitHub 개발 계획은 [상위 이슈 #32](https://github.com/HyeYeonLee0112/AdvancedJavaProgramming/issues/32)와 #33~#46을 기준으로 한다. 기존 릴레이 이슈 #20~#31은 기획 변경 사유로 닫았다. 착수 순서는 [따라 구현하기](포스트잇보드_따라구현하기.md)를 참고한다.
