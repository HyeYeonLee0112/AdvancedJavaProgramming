## 문서 읽는 방법

개발 문서는 시작 상태와 결과물 → 필요한 개념 → 지금 정할 것/미룰 것 → 파일 책임 → 실행 흐름 → 작은 예제 → 직접 구현 순서 → 실패 테스트 → 회고·완료 기준 순서다.

작은 예제를 실행하고 서비스 흐름은 직접 작성한다. 핵심 코드 전체나 제출 문서 전체를 제공하지 않는다. 막히면 작성한 코드와 첫 오류를 가져와 리뷰받는다.

#32는 전체 개발 계획 문서, #33~#46은 14개의 개발 문서다. 번호는 추천 읽기 순서이며 실제 착수 조건은 각 문서의 선행 이슈를 따른다.

## 먼저 확인할 미정 사항

JavaFX 사용·1인 개발 허용, RMI 필수 적용 여부는 교수자에게 확인한다. JavaFX 최종 버전·DB/드라이버·이미지 한도·참가 정책·비밀번호 해시 API·스냅샷 렌더링 방식은 해당 이슈에서 선택하고 근거를 기록한다. 예시 버전을 제품의 최종 확정으로 간주하지 않는다.

게임·그림판·채팅·AI 생성·무한 캔버스를 이 안내서에서 추가 확정하지 않는다. 포스트잇 색상은 후보 상태다.

## 코드 리뷰 요청 양식

```text
이슈:
만들려는 동작:
현재 파일과 직접 작성한 코드:
실행·입력 순서:
기대 결과:
실제 결과와 첫 오류:
내가 의심하는 원인:
확인한 경계값:
미정인 선택:
```

실제 실행 전에는 완료 체크하지 않는다. 각 문서의 테스트표에 기대와 실제를 구분해 기록하고, 검증한 증거로 이슈를 완료한다.
