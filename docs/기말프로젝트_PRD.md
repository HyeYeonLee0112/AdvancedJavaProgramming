# PRD — 포스트잇 협업 보드 (가칭)

상태: 합의된 기능을 추적하기 위한 작업 초안. 구현 완료 또는 제출 승인 문서가 아니다.
기획 변경: 글·그림 릴레이에서 포스트잇 협업 보드로 전환한다.

[기획서](기말프로젝트_기획서.md)와 함께 읽는다. 아래 완료 기준은 개발·시연으로 검증할 목표다. 기존 게임 요구사항 G-01~G-08, 그림판 요구사항 D-01~D-03과 게임용 검증 항목은 폐기한다. L·C·V 항목은 이번 기획에 맞춰 다시 정의하므로 기존 이슈의 ID만 보고 같은 의미로 해석하지 않는다.

## 1. 제품 목표와 기술 선택

여러 사용자가 같은 보드에 텍스트·이미지 포스트잇을 붙이고, 내용을 편집하거나 위치를 옮기며 생각을 정리한다. 보드 상태를 저장하고 스냅샷을 보관·공개할 수 있다.

- 혼자 사용하거나 다른 사용자가 공유 코드로 참여한다. 게임 시작이나 최소 참가 인원 조건은 없다.
- 참가자는 권한이 있는 보드의 전체 카드를 조회한다. 차례·타이머·문장 비공개·장면 배정은 없다.
- Eclipse, Temurin JDK 21, Maven, JavaFX, UTF-8을 유지한다.
- Java 서버가 인증·권한·수정 버전과 저장 결과를 판정한다.
- JDBC로 저장하고 소켓으로 같은 보드의 변경을 전달한다.
- JavaFX 버전, DB 제품·드라이버, 이미지 저장 방식은 미정이다.
- Swing 수업의 JavaFX 최종 프로젝트 사용 허용 여부는 교수자에게 확인한다.

## 2. 참고 서비스 구현 기능 — 전부 필수 기준선

근거 버전: `dev`, `7cc384ab5a8b47c54d789fa6c3d51fbef4bacec0`. 기존 코드 분석에 근거하며 실행·부하 검증 완료를 뜻하지 않는다. Java에서 동등한 사용자 동작으로 제공한다.

| ID | 유지할 기능 | 요구사항 및 완료 기준 |
|---|---|---|
| B-01 | 회원가입·로그인·로그아웃 | 인증에 따라 접근을 제한하고 로그아웃 후 쓰기를 차단한다. |
| B-02 | 보드 생성·내 보드 목록 | 사용자별 보드를 만들고 다시 찾는다. |
| B-03 | 보드 조회·제목 변경·공유 식별자 변경 | 공유 식별자로 보드에 참여하며 소유자가 제목·식별자를 변경한다. 식별자 변경 후 이전 코드로 신규 참여할 수 없다. 기존 참가자의 권한 유지 여부는 미정이다. |
| B-04 | 텍스트·이미지 카드 생성·조회·수정·삭제 | 보드에서 글·이미지 카드를 붙이고 수정·삭제하며 저장된 이미지를 다시 표시한다. |
| B-05 | 카드 드래그·겹침 순서 | 카드 위치와 표시 순서를 저장한다. 생성·수정·이동 후 최상단 표시 순서를 반영한다. 상세 동작은 참고 코드와 대조한다. |
| B-06 | 작성자·보드 소유자 권한 | 작성자는 자기 카드, 보드 소유자는 전체 카드를 관리한다. 보드 참가 여부와 편집 권한을 서버에서 검사한다. |
| B-07 | 글자 수·카드 수 제한 | 텍스트 500자, 보드당 카드 300개를 서버와 화면에서 검사한다. 동시 생성으로 카드 상한을 넘지 않는다. |
| B-08 | 버전 기반 수정 충돌 검사 | 이전 버전 수정·이동·삭제 요청을 거부하고 최신 상태를 다시 받을 수 있게 한다. 다른 사용자의 변경을 조용히 덮어쓰지 않는다. |
| B-09 | 보드별 실시간 변경 전파 | 생성·수정·이동·삭제 결과를 같은 보드에 접속한 사용자에게만 반영한다. |
| B-10 | 보드 삭제 전 이미지 스냅샷 보관 | 소유자가 보드를 삭제할 때 최종 이미지를 저장한다. 스냅샷 저장에 실패하면 보드를 삭제하지 않는 것을 기본 작업 정책으로 한다. |
| B-11 | 내 스냅샷·이미지 조회 | 저장된 스냅샷 목록과 이미지를 다시 연다. |
| B-12 | 스냅샷 공개 전환·공개 갤러리 | 소유자가 공개 여부를 변경한다. 기본 비공개이며 공개 해제 후 비소유자의 상세·이미지 재요청도 차단한다. |
| B-13 | 스냅샷 삭제 | 소유자만 스냅샷을 삭제한다. 삭제된 스냅샷은 목록과 이미지 조회에서 제외한다. |

스냅샷 공개 권한과 카드 편집 권한은 별개다. 일반 참가자는 다른 사용자의 카드나 소유자의 스냅샷 공개 상태를 변경할 수 없다. 참고 서비스의 100명 동시 접속 목표는 검증된 성능으로 간주하지 않는다.

## 3. 저장·통신·화면 품질 요구사항

| ID | 상태 | 요구사항 및 완료 기준 |
|---|---|---|
| L-01 | 필수 | 사용자·보드·참여 관계·카드·스냅샷을 JDBC로 저장하고 앱·서버 재실행 후 조회한다. |
| L-02 | 필수 | 카드 내용·작성자·좌표·겹침 순서·수정 버전이 저장 전후 동일하다. |
| L-03 | 필수 | 서버가 성공을 확인한 변경만 저장 성공으로 표시한다. 실패 시 오류와 최신 상태를 안내한다. |
| L-04 | 필수 | 연결이 끊기면 상태를 표시한다. 재접속 시 권한을 재확인하고 보드 전체 최신 상태를 받아 놓친 변경을 복구한다. |
| L-05 | 품질 기준 | 네트워크 수신·DB 대기·이미지 처리 중 화면이 반응한다. JavaFX 화면 갱신은 JavaFX 애플리케이션 스레드에서 한다. |
| L-06 | 필수 | 이미지 파일과 DB 기록의 일부 저장 실패를 처리한다. 저장 실패를 성공으로 표시하지 않고 재시도·잔여 파일 정리 정책을 정한다. |
| L-07 | 필수 | 삭제된 보드의 조회·수정 요청을 서버에서 거부하고 접속 중인 클라이언트에 삭제 사실을 알린다. |

게임 회차, 장면, 무작위 배정, 공동 원본·편집본 데이터는 사용하지 않는다. 저장 대상은 하나의 협업 보드와 그 카드, 보존용 스냅샷이다.

## 4. 간단한 썸네일 캐시

기존 캐시 결정을 스냅샷 보관함에 적용한다. 앱 실행 중 이미 받은 썸네일을 메모리에 보관하여 같은 이미지의 중복 다운로드를 줄인다.

| ID | 상태 | 요구사항 및 완료 기준 |
|---|---|---|
| C-01 | 필수 | 스냅샷 보관함의 320×180 이하 썸네일을 저장하고 같은 스냅샷·같은 버전 조회 시 다시 다운로드하지 않는다. |
| C-02 | 필수 | 최대 50개를 유지하고 한도를 넘으면 가장 오래 사용하지 않은 항목부터 제거한다. 원본 이미지는 캐시하지 않는다. |
| C-03 | 필수 | 스냅샷 변경·삭제·공개 상태 변경 시 해당 캐시를 제거하며 로그아웃 시 전체를 비운다. |
| C-04 | 필수 | 스냅샷 ID와 버전을 캐시 키로 사용한다. 서버 조회 권한을 확인한 뒤 캐시 이미지를 표시한다. |
| C-05 | 품질 기준 | 적중·미적중·제거를 로그나 카운터로 확인한다. 캐시 실패가 보관함 조회 실패로 이어지지 않는다. |

스냅샷 원본 이미지는 생성 후 고정하지만, 공개 상태 등 메타데이터 변경은 버전에 반영한다. 디스크·서버 캐시는 초기 범위에 포함하지 않는다.

## 5. 책임 분리와 학습 방향

- 화면: JavaFX로 보드 목록, 카드 편집·드래그, 저장·연결 상태, 보관함·갤러리를 표시한다.
- 편집 규칙: 서버가 카드 제한, 소유·작성자 권한, 수정 버전을 검사한다.
- 통신: 로그인·보드 참여·편집 요청과 서버 결과를 전달한다. 서버 승인된 변경을 같은 보드에 알린다.
- 저장: JDBC로 사용자·보드·참여자·카드·스냅샷을 관리한다.
- 이미지 처리: 이미지 미리보기·보드 스냅샷·썸네일을 생성하고 저장·전송한다.
- 학습: 이벤트 → 카드 편집 → 소켓 동기화 → JDBC 저장 → 충돌 처리 → 캐시 순으로 작은 결과물을 연결한다.

클래스 전체 설계, DB 스키마, 통신 명세와 핵심 구현은 학습·구현 과정에서 사용자가 구체화한다.

| V-02 | 카드 생성·수정·삭제·이동과 겹침 순서가 두 클라이언트에 일치한다. |
| V-03 | 다른 보드 사용자에게 변경 이벤트와 비공개 데이터가 전달되지 않는다. |
| V-04 | 일반 참가자의 타인 카드 편집·보드 관리·스냅샷 공개 변경 요청을 서버가 거부한다. |
| V-05 | 500자/501자, 카드 300개/301개와 동시 생성에서 제한이 지켜진다. |

| V-07 | 재실행 후 내용·작성자·좌표·겹침 순서·버전이 복원된다. |
| V-08 | 연결 끊김과 재접속 후 최신 보드 상태가 복구되고 실패를 성공으로 표시하지 않는다. |
| V-09 | 느린 이미지 전송과 DB 대기 중에도 화면이 반응한다. |
| V-10 | 보드 삭제 전 스냅샷이 저장되며 저장 실패 시 보드가 남는다. 삭제된 보드의 후속 요청은 거부한다. |
| V-11 | 비공개 스냅샷의 목록·상세·이미지 접근을 차단하고 공개·공개 해제·삭제가 반영된다. |
| V-12 | 같은 썸네일의 중복 다운로드가 줄고 51번째 항목에서 가장 오래 사용하지 않은 항목이 제거된다. |
| V-13 | 로그아웃·삭제·공개 상태 변경 후 오래된 캐시를 표시하지 않는다. |
| V-14 | 입장·카드 작성·이동·두 화면 동기화·재조회·스냅샷 확인을 5분 내 시연한다. |

## 7. 추가 후보와 미정 사항

- 포스트잇 색상 선택: 추가 기능 후보. 아직 필수 요구로 확정하지 않는다.
- 제품명과 대표 사용 상황, 구체적인 화면 디자인.
- 보드 크기와 지원 인원 상한, 이미지 용량·형식.
- 공유 코드 참여·보드 접근 정책과 코드 변경 후 기존 참가자의 처리.
- 보드 공개와 스냅샷 공개의 관계. 공개 갤러리는 스냅샷 기준으로 우선 적용한다.
- JavaFX 버전, DB 제품·드라이버, 이미지 저장 방식.
- 교수자의 JavaFX 사용·1인 개발 허용 여부.

직접 그리는 그림판은 이번 전환에서 필수 범위에서 제외한다. AI 생성, 채팅, 무한 캔버스는 추가 확정하지 않는다. GitHub 개발 계획은 [상위 이슈 #32](https://github.com/HyeYeonLee0112/AdvancedJavaProgramming/issues/32)와 #33~#46을 기준으로 한다. 기존 #20~#31은 기획 변경 사유로 닫았다. [따라 구현하기](포스트잇보드_따라구현하기.md)에 각 이슈의 학습·구현·검증 순서를 연결했다.
