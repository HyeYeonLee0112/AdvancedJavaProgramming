# PRD — 글·그림 릴레이 (가칭)

상태: 합의된 기능을 추적하기 위한 작업 초안. 구현 완료 또는 제출 승인 문서가 아니다.

[기획서](기말프로젝트_기획서.md)의 결정과 미정 사항을 함께 읽는다. 아래 완료 기준은 개발·시연으로 검증할 목표이며 현재 통과했다는 의미가 아니다.

## 1. 제품 목표와 경계

- 참가자가 한 문장씩 만든 이야기를 다른 참가자가 그림으로 해석하고 공동 공개한다.
- 완성작을 저장하고 재실행 후 감상·공개·편집본 제작에 사용한다.
- 4~6인, 글쓰기 20초/인, 그림 동시 작성 60초로 5분 이내 체험을 목표로 한다.
- JavaFX 데스크톱 클라이언트와 Java 서버를 대상으로 한다. 개발 환경은 Eclipse, Temurin JDK 21, Maven이다. DB 제품과 이미지 저장 방식은 미정이다.
- 실시간 공동 캔버스, AI 생성, 채팅, 무한 캔버스, 100명 접속은 현재 필수로 확정하지 않는다.

### 기술 결정

| 항목 | 결정 | 비고 |
|---|---|---|
| GUI | JavaFX | 방·문장·그림판·결과·보관함 화면에 사용 |
| 드로잉 | JavaFX `Canvas`, `GraphicsContext` | 마우스 이벤트로 획을 수집하고 화면에 그림 |
| 빌드 | Maven | JavaFX·JDBC 드라이버 등 외부 라이브러리와 빌드 관리 |
| Java | Temurin JDK 21 | Maven 컴파일 대상도 21로 통일 |
| 인코딩 | UTF-8 | 한글 문장과 문서 처리 |

수업의 실제 중심 GUI 범위가 Swing이므로 JavaFX 사용 허용 여부는 교수자 확인 항목이다. Swing 주차 실습은 별도로 수행하고, 이벤트·레이아웃·그래픽 원리가 JavaFX에서 어떻게 대응되는지 설명할 수 있어야 한다.

## 2. 게임 진행 요구사항

| ID | 상태 | 요구사항 및 완료 기준 |
|---|---|---|
| G-01 | 필수 | 4~6명 접속·준비 완료 시 방 개설자가 시작한다. 3명 이하 시작과 7번째 입장을 차단한다. 시작 명단을 고정하고 게임 중 신규 입장을 차단한다. |
| G-02 | 필수 | 시작 소재와 작성 순서를 제공한다. 소재 공급·순서 결정 방식은 미정이다. |
| G-03 | 필수 | 차례인 참가자가 20초 동안 한 문장을 작성한다. 현재 작성자에게 직전 문장 하나만 전달한다. 누적 이야기·타인 과제는 서버에서도 노출하지 않는다. 공통 소재는 표시한다. |
| G-04 | 필수 | N명 작성 후 N개 장면의 순서와 작성자를 유지한다. 각 장면을 다른 작성자에게 정확히 한 번 배정한다. |
| G-05 | 필수 | 각자 배정된 장면을 기본 60초 동안 동시에 그린다. 타인의 미공개 그림에 접근할 수 없다. |
| G-06 | 필수 | 종료 후 모든 참가자가 같은 작품을 원래 문장 순서로 볼 수 있다. 공개 연출 방식은 미정이다. |
| G-07 | 필수 | 서버가 현재 단계·차례·마감을 판정한다. 중복 제출과 이전 단계의 지연 요청으로 결과나 차례가 중복 변경되지 않는다. |
| G-08 | 필수 | 아래 기본 진행·실패 정책을 적용한다. 참가자 이탈·빈 제출로 회차가 무기한 대기하지 않는다. |

### 기본 진행·실패 정책

- 수동 문장 제출은 차례를 확정하고 다음 사람으로 진행한다. 마감까지 미제출이면 서버가 수신한 마지막 비어 있지 않은 초안을 확정한다. 초안은 변경 시 최대 초당 1회 및 입력 정지 시 전송하고 저장 상태를 표시한다.
- 초안이 비면 ‘그러던 중, 예상하지 못한 일이 벌어졌다.’로 대체한다. 첫 문장이 비면 ‘[소재]에 관한 이야기가 시작되었다.’로 대체한다. 대체 장면에는 시스템 생성 표시를 남겨 참가자의 실제 글로 오인하지 않게 한다.
- 게임 중 사용자는 현재 과제만 열 수 있다. 과거에 본 문장을 사람이 기억하는 것은 막을 수 없으나, 이전 전체 이력을 재조회하는 기능은 제공하지 않는다.
- 그림은 60초 동안 수정 가능하다. 마감 시 클라이언트 입력을 잠그고 최종 전송을 시작한다. 최대 5초 수신 구간 이후 서버가 장면을 확정한다. 수신 구간은 그리기 시간 연장이 아니며, 초기 시제품에서 악성 클라이언트의 실제 입력 시각까지 증명하지는 않는다.
- 그림이 변경되면 최대 5초마다 초안을 전송한다. 서버가 받은 최신 순번을 유지한다. 최종 이미지 수신 실패 시 최신 저장 초안, 초안도 없으면 ‘그림 미제출’ 표시를 사용한다. 종료 후 지연 전송으로 원본을 바꾸지 않는다.
- 이탈해도 타이머·시작 명단·배정을 유지한다. 같은 계정으로 재접속 시 현재 차례·마감·자신의 허용된 초안을 복원한다. 이미 마감된 과제는 다시 제출할 수 없다.
- 방 개설자 이탈도 동일하게 처리하며 진행은 서버가 맡는다. 참가자 전원 이탈 시에도 서버가 정상이라면 제한 시간대로 회차를 마무리한다. 서버 장애 시 회차 자동 복구는 초기 범위 밖이며 중단 사실을 표시한다.

## 3. 드로잉 요구사항

| ID | 상태 | 요구사항 및 완료 기준 |
|---|---|---|
| D-01 | 필수 | JavaFX `Canvas`에서 마우스로 직접 그린 결과를 해당 장면의 그림으로 제출하고 다시 표시할 수 있다. |
| D-02 | 필수 | 펜, 펜 색상 설정, 지우개, 획 단위 되돌리기를 제공한다. 한 번의 드래그를 한 획으로 처리하며 지우개 작업도 되돌린다. 빈 이력에서는 되돌리기를 비활성화한다. |
| D-03 | 품질 기준 | 이미지 처리·전송 중에도 화면이 응답한다. 실패한 제출을 성공으로 표시하지 않는다. |

다시 실행, 굵기 선택, 전체 지우기는 선택 확장이다. 글자 입력 도구는 현 요구에 포함하지 않는다. 색상 설정은 그리는 펜의 색상으로 해석한다.

## 4. 완성작 보관함 요구사항

| ID | 상태 | 요구사항 및 완료 기준 |
|---|---|---|
| L-01 | 필수 | 완성작을 JDBC로 영속 관리한다. 앱·서버 재실행 후 저장된 작품을 조회할 수 있다. |
| L-02 | 필수 | 문장·그림 참조·장면 순서·글쓴이·그린 사람의 대응이 저장 전후 동일하다. |
| L-03 | 필수 | 시작 명단의 참가자 전원이 완성작을 공동 소유하고 각자 보관함에서 상세 보드를 연다. 이탈자는 소유권을 잃지 않는다. 참가자별 복제 원본 대신 한 원본과 참가자 관계를 유지한다. |
| L-04 | 필수 | 기본 비공개이며 방 개설자만 공개 여부를 변경한다. 일반 참가자는 공동 소유자여도 변경할 수 없다. 서버가 검사하며 시작 전 규칙을 알린다. 공개 해제 후 갤러리·이미지 재요청도 비참가자에게 차단한다. 이미 내려받은 사본 회수는 보장하지 않는다. |
| L-05 | 필수 | 별도 편집본을 만든다. 편집본의 카드 이동·수정·삭제가 원본 결과에 영향을 주지 않는다. |
| L-06 | 결정 필요 | 공동 원본의 전체 삭제 정책과 첨부 이미지 정리를 정한다. 확정 전 공동 원본 전체 삭제는 제공하지 않는다. 개인 편집본·스냅샷 삭제와 구분한다. |

게임 원본에서 생성한 스냅샷·편집본을 포함해 공개 권한은 원래 방 개설자에게 유지한다. 개인 편집본의 카드 편집 권한과 공동 작품 공개 권한을 구분하여, 복사본을 통한 공개 권한 우회를 막는다. 별도로 만든 일반 보드는 기존 B-06/B-12의 소유자 규칙을 유지한다.

## 5. 캐싱 요구사항

캐시는 서버의 원본 데이터를 대신하는 저장소가 아니라, 이미 받은 완성작 썸네일을 빠르게 다시 보여주기 위한 클라이언트 메모리 보조 기능이다.

| ID | 상태 | 요구사항 및 완료 기준 |
|---|---|---|
| C-01 | 필수 | 완성작 보관함에서 한 번 받은 320×180 이하 썸네일을 메모리에 저장하고, 같은 작품·같은 수정 버전 재조회 시 서버에서 다시 내려받지 않는다. |
| C-02 | 필수 | 최대 50개를 저장하며 한도를 넘으면 가장 오래 사용하지 않은 썸네일부터 제거한다. 원본 크기 그림은 캐시하지 않는다. |
| C-03 | 필수 | 작품 수정·삭제·공개 상태 변경 시 해당 작품 캐시를 제거하고, 로그아웃 시 전체 캐시를 비운다. |
| C-04 | 필수 | 캐시 키에 작품 ID와 수정 버전을 포함한다. 서버에서 조회 권한을 확인한 뒤에만 캐시 이미지를 화면에 표시한다. |
| C-05 | 품질 기준 | 캐시 적중·미적중·제거를 개발 로그나 카운터로 확인할 수 있다. 캐시 실패가 보관함 조회 실패로 이어지지 않는다. |

메모리 캐시만 초기 범위에 포함한다. 디스크 캐시, 여러 사용자가 공유하는 서버 캐시와 게임 진행 상태 캐시는 포함하지 않는다.

## 6. 참고 서비스 구현 기능 — 전부 필수 기준선

근거 버전: `dev`, `7cc384ab5a8b47c54d789fa6c3d51fbef4bacec0`. 코드 확인을 기준으로 하며, 실행·부하 검증을 완료했다는 의미는 아니다. 아래 기능은 Java에서 동등한 사용자 동작으로 제공한다. Flask·MongoDB·S3 등 구현 제품 자체를 복제할 의무는 없다.

| ID | 유지할 기능 | 적용 위치·완료 기준 |
|---|---|---|
| B-01 | 회원가입·로그인·로그아웃 | 인증에 따라 기능 접근이 달라지고 로그아웃 후 쓰기를 차단한다. |
| B-02 | 보드 생성·내 보드 목록 | 사용자별 보드를 만들고 다시 찾는다. |
| B-03 | 보드 조회·제목 변경·공유 식별자 변경 | 공유 경로로 조회하고 소유자가 제목·공유 식별자를 변경한다. 데스크톱 참여 코드와의 관계는 설계에서 정한다. |
| B-04 | 텍스트·이미지 카드 생성·조회·수정·삭제 | 종료 후 편집본에서 제공한다. 이미지를 첨부하고 다시 표시할 수 있다. |
| B-05 | 카드 드래그·겹침 순서 | 위치를 저장하고, 생성·수정·이동 후 최상단 표시 순서를 반영한다. 상세 UI 동작은 원본 코드와 대조한다. |
| B-06 | 작성자·보드 소유자 권한 | 작성자는 자기 카드, 보드 소유자는 전체 카드를 관리한다. 서버에서 검사한다. |
| B-07 | 글자 수·카드 수 제한 | 기존 기준인 텍스트 500자, 보드당 카드 300개를 유지한다. 게임 문장의 별도 길이 제한은 미정이다. |
| B-08 | 버전 기반 수정 충돌 검사 | 이전 버전으로 수정하면 다른 사용자의 변경을 덮어쓰지 않고 충돌을 알린다. |
| B-09 | 보드별 실시간 생성·수정·이동·삭제 전파 | 편집본에서 같은 보드 참가자에게만 변경을 반영한다. |
| B-10 | 보드 삭제 전 이미지 스냅샷 보관 | 소유자가 삭제할 때 최종 이미지를 남긴다. 저장 실패 시 삭제 진행 정책을 명시한다. |
| B-11 | 내 스냅샷·이미지 조회 | 저장된 스냅샷 목록과 이미지를 다시 연다. |
| B-12 | 스냅샷 공개 전환·공개 갤러리 | 소유자가 공개 상태를 관리하고 비공개 이미지 접근을 제한한다. |
| B-13 | 스냅샷 삭제 | 소유자가 스냅샷을 삭제한다. 기존 대화의 목록에서 빠졌으나 원본 코드에 존재하는 기능이다. |

참고 서비스 문서의 100명 동시 접속은 검증된 성능으로 간주하지 않는다. 공유 식별자 변경·보드 삭제 시 접속자 무효화는 원본에 미완성 부분이 있어 개선 검토 항목이다. 기존 구현의 오류를 재현하는 것이 목표는 아니다.

## 7. 책임 분리와 데이터 초안

- 화면: JavaFX로 문장 입력·그리기·진행 상태·작품을 표시한다. 백그라운드 작업 결과는 JavaFX 애플리케이션 스레드에서 반영한다.
- 진행 제어: 방, 참가자 순서, 단계, 배정, 제출 판정. 서버가 기준을 관리한다.
- 통신: 요청과 결과·진행 알림 전달. 네트워크 대기를 화면 처리에서 분리.
- 저장: 사용자, 게임 회차, 참가자, 장면, 제출 그림 참조, 완성작, 편집본 카드, 스냅샷 관리.
- 그림 파일을 DB 외부에 둘 수 있다. 파일과 DB 기록 중 일부만 저장되는 실패를 처리해야 한다.
- 클래스 전체 설계·DB 스키마·통신 명세는 학습과 구현 과정에서 사용자가 구체화한다.

| V-03 | 이전 단계의 요청과 타인 장면 조회가 서버에서 거부된다. |
| V-04 | 느린 이미지 전송 중 그림판·진행 화면이 멈추지 않는다. |
| V-05 | 재실행 후 작품 내용·순서·작성자 정보가 일치한다. |
| V-06 | 비공개 작품·스냅샷을 권한 없는 계정이 열 수 없다. |
| V-07 | 편집본 변경 후 원본은 동일하며, 동시 수정 충돌을 처리한다. |
| V-08 | 실제 참가자 시연에서 입장부터 결과 감상까지 300초 이내다. |
| V-09 | 3명은 시작 불가, 4·5·6명은 진행 가능, 7번째 참가자는 입장 불가이며 게임 중 참가자 수를 재편하지 않는다. |
| V-10 | 공동 소유 참가자의 조회는 허용하지만 공개 변경은 거절한다. 방 개설자만 공개·비공개를 바꿀 수 있다. |
| V-11 | 빈 문장·그림, 작성자 이탈, 방 개설자 이탈, 마감 후 재접속에서 다음 단계·대체 표시·접근 권한이 정책과 일치한다. |
| V-12 | 지우개 한 획을 되돌리면 지우기 전 상태로 복원하며, 되돌릴 작업이 없을 때 오류가 없다. |
| V-13 | 보관함을 두 번 열 때 변경되지 않은 썸네일을 중복 다운로드하지 않으며, 51번째 캐시 항목에서 가장 오래 사용하지 않은 항목을 제거한다. |
| V-14 | 로그아웃·작품 삭제·수정·공개 상태 변경 뒤 오래된 캐시 이미지를 표시하지 않는다. |

## 9. 다음 사용자 결정

인원·공개 범위·작품 소유·공개 권한·필수 그림판 도구는 사용자 결정으로 확정했다. 시간 초과·빈 제출·이탈·재접속은 위임에 따라 기본 정책을 정했다.

준비 30초 + 글쓰기 80~120초 + 그림 60초 + 최종 전송 최대 5초 + 감상 60초 = 235~275초를 시연 목표로 한다. 나머지는 단계 전환·통신 여유다. 실제 참가자 검증은 필요하다.

남은 결정은 소재 공급·순서 결정 방식, 제품명, 공개 연출, 공동 원본 전체 삭제 정책, DB 제품과 JavaFX 버전이다. JavaFX 사용 허용 여부도 교수자에게 확인한다. 문서 작성만으로 구현이나 검증을 완료한 것으로 표시하지 않는다.
