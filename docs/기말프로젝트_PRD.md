# PRD — 글·그림 릴레이 (가칭)

상태: 합의된 기능을 추적하기 위한 작업 초안. 구현 완료 또는 제출 승인 문서가 아니다.

[기획서](기말프로젝트_기획서.md)의 결정과 미정 사항을 함께 읽는다. 아래 완료 기준은 개발·시연으로 검증할 목표이며 현재 통과했다는 의미가 아니다.

## 1. 제품 목표와 경계

- 참가자가 한 문장씩 만든 이야기를 다른 참가자가 그림으로 해석하고 공동 공개한다.
- 완성작을 저장하고 재실행 후 감상·공개·편집본 제작에 사용한다.
- 5분 이내 체험이 목표다. 참여 인원과 인원별 시간 규칙은 미정이다.
- Java 데스크톱 클라이언트와 서버를 대상으로 한다. DB 제품과 이미지 저장 방식은 미정이다.
- 실시간 공동 캔버스, AI 생성, 채팅, 무한 캔버스, 100명 접속은 현재 필수로 확정하지 않는다.

## 2. 게임 진행 요구사항

| ID | 상태 | 요구사항 및 완료 기준 |
|---|---|---|
| G-01 | 필수 | 방에 참가자 목록을 표시한다. 시작 조건과 정원은 미정 규칙 확정 후 검증한다. |
| G-02 | 필수 | 시작 소재와 작성 순서를 제공한다. 소재 공급·순서 결정 방식은 미정이다. |
| G-03 | 필수 | 차례인 참가자가 기본 20초 동안 한 문장을 작성한다. 다음 참가자에게 직전 문장을 전달한다. |
| G-04 | 필수 | N명 작성 후 N개 장면의 순서와 작성자를 유지한다. 각 장면을 다른 작성자에게 정확히 한 번 배정한다. |
| G-05 | 필수 | 각자 배정된 장면을 기본 60초 동안 동시에 그린다. 타인의 미공개 그림에 접근할 수 없다. |
| G-06 | 필수 | 종료 후 모든 참가자가 같은 작품을 원래 문장 순서로 볼 수 있다. 공개 연출 방식은 미정이다. |
| G-07 | 설계 제안 | 서버가 현재 단계·차례·마감을 판정한다. 중복 제출과 이전 단계의 지연 요청으로 결과나 차례가 중복 변경되지 않는다. |
| G-08 | 결정 필요 | 빈 제출·시간 초과·이탈·재접속 처리 정책을 확정한 후, 게임이 무기한 대기하지 않음을 검증한다. |

## 3. 드로잉 요구사항

| ID | 상태 | 요구사항 및 완료 기준 |
|---|---|---|
| D-01 | 필수 | 마우스로 직접 그린 결과를 해당 장면의 그림으로 제출하고 다시 표시할 수 있다. |
| D-02 | 제안 | 펜 색상·굵기 선택, 획 단위 실행 취소·다시 실행, 전체 지우기를 제공한다. 세부 도구 범위는 미확정이다. |
| D-03 | 품질 기준 | 이미지 처리·전송 중에도 화면이 응답한다. 실패한 제출을 성공으로 표시하지 않는다. |

## 4. 완성작 보관함 요구사항

| ID | 상태 | 요구사항 및 완료 기준 |
|---|---|---|
| L-01 | 필수 | 완성작을 JDBC로 영속 관리한다. 앱·서버 재실행 후 저장된 작품을 조회할 수 있다. |
| L-02 | 필수 | 문장·그림 참조·장면 순서·글쓴이·그린 사람의 대응이 저장 전후 동일하다. |
| L-03 | 필수 | 작품 목록에서 상세 보드를 연다. 조회 가능한 작품의 범위는 소유·참가자 정책에 따른다. |
| L-04 | 필수 | 권한 있는 사용자가 공개 여부를 바꾼다. 공개 갤러리에 비공개 작품이 노출되지 않는다. 공개 권한·동의 정책은 미정이다. |
| L-05 | 필수 | 별도 편집본을 만든다. 편집본의 카드 이동·수정·삭제가 원본 결과에 영향을 주지 않는다. |
| L-06 | 결정 필요 | 작품과 기존 이미지 스냅샷의 관계, 원본 삭제·보존 및 첨부 이미지 정리 정책을 정한다. |

## 5. 참고 서비스 구현 기능 — 전부 필수 기준선

근거 버전: `dev`, `7cc384ab5a8b47c54d789fa6c3d51fbef4bacec0`. 코드 확인을 기준으로 하며, 실행·부하 검증을 완료했다는 의미는 아니다. 아래 기능은 Java에서 동등한 사용자 동작으로 제공한다. Flask·MongoDB·S3 등 구현 제품 자체를 복제할 의무는 없다.

| ID | 유지할 기능 | 적용 위치·완료 기준 |
|---|---|---|
| B-01 | 회원가입·로그인·로그아웃 | 인증에 따라 기능 접근이 달라지고 로그아웃 후 쓰기를 차단한다. |
| B-02 | 보드 생성·내 보드 목록 | 사용자별 보드를 만들고 다시 찾는다. |
| B-03 | 보드 조회·제목 변경·공유 식별자 변경 | 공유 경로로 조회하고 소유자가 제목·공유 식별자를 변경한다. 데스크톱 참여 코드와의 관계는 설계에서 정한다. |
| B-04 | 텍스트·이미지 카드 생성·조회·수정·삭제 | 종료 후 편집본에서 제공한다. 이미지를 첨부하고 다시 표시할 수 있다. |
| B-05 | 카드 드래그·겹침 순서 | 위치를 저장하고, 생성·수정·이동 후 최상단 표시 순서를 반영한다. 상세 UI 동작은 원본 코드와 대조한다. |
| B-06 | 작성자·보드 소유자 권한 | 작성자는 자기 카드, 보드 소유자는 전체 카드를 관리한다. 서버에서 검사한다. |
| B-07 | 글자 수·카드 수 제한 | 기존 기준인 텍스트 500자, 보드당 카드 300개를 유지한다. 게임 문장의 별도 길이 제한은 미정이다. |
| B-08 | 버전 기반 수정 충돌 검사 | 이전 버전으로 수정하면 다른 사용자의 변경을 덮어쓰지 않고 충돌을 알린다. |
| B-09 | 보드별 실시간 생성·수정·이동·삭제 전파 | 편집본에서 같은 보드 참가자에게만 변경을 반영한다. |
| B-10 | 보드 삭제 전 이미지 스냅샷 보관 | 소유자가 삭제할 때 최종 이미지를 남긴다. 저장 실패 시 삭제 진행 정책을 명시한다. |
| B-11 | 내 스냅샷·이미지 조회 | 저장된 스냅샷 목록과 이미지를 다시 연다. |
| B-12 | 스냅샷 공개 전환·공개 갤러리 | 소유자가 공개 상태를 관리하고 비공개 이미지 접근을 제한한다. |
| B-13 | 스냅샷 삭제 | 소유자가 스냅샷을 삭제한다. 기존 대화의 목록에서 빠졌으나 원본 코드에 존재하는 기능이다. |

참고 서비스 문서의 100명 동시 접속은 검증된 성능으로 간주하지 않는다. 공유 식별자 변경·보드 삭제 시 접속자 무효화는 원본에 미완성 부분이 있어 개선 검토 항목이다. 기존 구현의 오류를 재현하는 것이 목표는 아니다.

## 6. 책임 분리와 데이터 초안

- 화면: 문장 입력·그리기·진행 상태·작품 표시. Swing 화면 갱신 규칙 준수.
- 진행 제어: 방, 참가자 순서, 단계, 배정, 제출 판정. 서버를 기준으로 처리하는 방안 제안.
- 통신: 요청과 결과·진행 알림 전달. 네트워크 대기를 화면 처리에서 분리.
- 저장: 사용자, 게임 회차, 참가자, 장면, 제출 그림 참조, 완성작, 편집본 카드, 스냅샷 관리.
- 그림 파일을 DB 외부에 둘 수 있다. 파일과 DB 기록 중 일부만 저장되는 실패를 처리해야 한다.
- 클래스 전체 설계·DB 스키마·통신 명세는 학습과 구현 과정에서 사용자가 구체화한다.

## 7. 검증 항목

| ID | 검증할 결과 |
|---|---|
| V-01 | 확정한 지원 인원별로 자기 문장 배정·장면 중복·누락이 없다. |
| V-02 | 수동 제출과 마감 처리가 겹쳐도 한 장면·한 차례만 확정된다. |
| V-03 | 이전 단계의 요청과 타인 장면 조회가 서버에서 거부된다. |
| V-04 | 느린 이미지 전송 중 그림판·진행 화면이 멈추지 않는다. |
| V-05 | 재실행 후 작품 내용·순서·작성자 정보가 일치한다. |
| V-06 | 비공개 작품·스냅샷을 권한 없는 계정이 열 수 없다. |
| V-07 | 편집본 변경 후 원본은 동일하며, 동시 수정 충돌을 처리한다. |
| V-08 | 실제 참가자 시연에서 입장부터 결과 감상까지 300초 이내다. |

## 8. 다음 사용자 결정

인원 범위, 준비·감상 시간, 시간 초과·빈 제출, 이탈·재접속, 문장 공개 범위, 작품 소유·공개 동의, 드로잉 도구를 결정한다. 문서 작성만으로 구현이나 검증을 완료한 것으로 표시하지 않는다.
